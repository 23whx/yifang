# In-app browser playtest — 2026-09-12

All eight play routes checked in the Codex in-app browser using UI actions, not injected game state.

## Coverage

- Xiangqi: C2=5 opening, AI H8+7 response, undo to starting position, choose black, local mode and flip.
- Chess: rejected e2-e5; e2-e4 followed by AI e7-e6; new game; local f3 e5 g4 Qh4# shows Black wins; further moves rejected; undo resumes play.
- Shogi: P-7f, AI S-3b, undo returns to initial state.
- Go: E5 placement, AI white response, undo removes both moves; local double-pass, resume, double-pass and score (empty board 0–7.5); new game and 19x19 selection.
- Cube: animated scramble, reset to solved, actual sticker drag turns a layer.
- Mahjong, Holdem, Baccarat: play routes show placeholder pages. There is no implemented match to play; this is missing functionality, not a passed gameplay test.

## Reproduced and corrected

1. Shared board flip fails after choosing AI black then switching to local play. Before fix, the top-left button remains a10 in Xiangqi both before and after flip. Cause: flipped view used the previous human side instead of the current mode's base orientation. Extracted boardOrientation and covered all eight mode/side/flip combinations.
2. Card/tile placeholder pages misleadingly say “Board in progress” and promise specific match modes. Reworded both languages to explicitly state that only lessons are available and matches are not yet playable.

## Environment

Port 3000 was initially stopped. Dev server subsequently stalled during initial compilation. Existing production build served the routes successfully; no security settings changed.

## Limits

This is a smoke/regression pass, not exhaustive rule certification. Long matches, every promotion/drop/endgame combination, touch devices and cross-device remote rooms were not covered. Existing rule suite adds independent fixture coverage.
